# 一、估值业务

1.基金资产净值（NAV）如何计算？

    NAV = (基金总资产 - 基金总负债) / 基金总份额
    总资产：股票、债券、现金等持仓市值 + 应收利息/股利
    总负债：应付管理费、托管费、交易费用、赎回款等

关键点：需按交易日收盘价进行公允价值计量。

2.基金估值的基本流程是怎样的？

    (1)数据采集：获取交易记录、证券价格（交易所/中证估值）、利率汇率等。
    
    (2)资产计价：
        股票：按交易所收盘价；
        债券：按中债/中证估值或第三方定价；
        衍生品：按模型（如Black-Scholes）或市场报价。
    
    (3)计提费用：计算当日应付管理费、托管费（按年费率/365摊提）。
    
    (4)负债确认：记录应付赎回款、交易结算款等。
    
    (5)NAV计算：复核数据 → 计算净值 → 交叉验证 → 报送监管/披露。

3.遇到停牌股票如何估值？

根据《基金估值指引》处理：

    短期停牌：使用最近交易日收盘价；
    长期停牌：采用估值模型（如指数收益法、可比公司市盈率法），需托管行复核并公告方法。

4.债券利息如何计提？

    应计利息 = 票面利率 × 债券面值 × 持有天数/计息周期天数
    关键点：每日计提利息收入；付息日需重置应计利息为零。

5.估值误差超过0.5%怎么办？

    立即启动应急预案：复核数据源、计算过程；
    分析原因：价格源错误？份额计算错误？
    纠正措施：调整净值，必要时由基金管理人赔偿投资者损失；
    报告：向监管报备并公告说明。

6.如何确保估值数据准确性？

    多重校验：独立三方数据比对（彭博/路透 vs 中债）；
    系统控制：估值系统设置价格偏离阈值报警；
    人工复核：双人审核关键数据（如大宗交易价格）；
    定期审计：内审/托管行检查估值流程。

7.开放式基金申购/赎回如何影响NAV？

    申购：现金增加 → 总资产增加 → NAV不变（份额同步增加）；
    赎回：现金减少 → 总资产减少 → NAV不变（份额减少）。
    注：大额赎回可能导致费用分摊变化（如赎回费计入基金资产）。

8.你如何应对估值截止时间压力？

    优先级管理：先处理价格波动大的资产（如港股、衍生品）；
    自动化工具：使用脚本自动抓取交易所数据；
    提前准备：开盘前确认当日需处理的特殊事项（如分红除权）；
    团队协作：与交易、运营实时沟通异常情况。

10.新金融工具准则（IFRS 9）对估值的影响？

    分类变化：资产按“摊余成本”或“公允价值”分类，影响计量方式；
    减值模型：预期信用损失（ECL）取代已发生损失模型；
    披露要求：增加敏感性分析和层级披露（L1~L3）。

11.如何优化估值流程？

    系统升级：部署智能估值平台（如自动抓取彭博数据）；
    标准化文档：建立估值操作手册（含特殊案例处理）；
    跨部门协同：与IT部门开发实时监控仪表盘。

12.基金的单位净值、累计净值有什么区别，这两个净值为什么会有差异？

定义与区别

    (1)单位净值
    定义：单位净值是指基金当前每份的实际价值，计算公式为：单位净值 = (基金总资产 - 基金总负债)/基金总份额
    特点：反映基金当前的实时价值，是申购、赎回基金的直接依据。已扣除历史分红（如分红后净值会下降）。

    (2)累计净值
    定义：累计净值是基金单位净值加上自成立以来所有分红金额的总和，计算公式为：累计净值 = 单位净值+成立以来每份累计分红总额
    特点： 包含了基金成立以来的全部收益（包括分红），能更全面地反映基金的长期表现。 不受分红或拆分操作的影响（分红后单位净值下降，但累计净值保持增长趋势）。

    累计净值包含了基金成立以来的所有分红，而单位净值是当前价值（已扣除分红）。两者差异越大，说明基金历史分红越多，长期收益能力越强。

为什么会有差异？

    (1)分红导致差异
    当基金分红时，单位净值会下降（因为分红是从基金资产中分配出去的），而累计净值会加上分红金额。 示例： 某基金单位净值为2元，分红0.5元后，单位净值变为1.5元，但累计净值变为2元。
    (2)拆分操作影响 
    基金拆分会降低单位净值（如1元拆成0.5元），但累计净值不变（因为拆分只是份额增加，不改变总资产）。
    (3)基金成立时间长短
    累计净值反映的是基金从成立至今的总收益，而单位净值仅反映当前价值。示例： 一只成立5年的基金，累计净值可能远高于单位净值（如累计净值3元，单位净值1.8元），说明它历史上多次分红。

如何理解两者的差异？

    单位净值：适合短期投资者参考，用于判断当前买入或赎回的成本。
    累计净值：更适合长期投资者参考，能直观体现基金的历史收益能力。

常见误区

    “单位净值低=便宜”
    错误！单位净值低可能是基金频繁分红或拆分导致的，并非业绩差。例如，一只基金累计净值高（如3元），但因多次分红，单位净值可能只有1元。

    “累计净值高=好基金”
    不完全正确！需结合基金的运作时间和风险水平综合判断。例如，一只成立10年的基金累计净值高，但近年表现不佳，可能不如成立3年但累计净值快速上升的基金。

二、恒生估值系统

1.日初准备与系统检查

    交易日初始化
        登录系统后设置当日为“当前记账日期”，确认交易日历（含节假日和非交易工作日）。
        检查系统参数：包括汇率、利率（如Shibor/LPR）、两费（管理费/托管费）计提规则、业绩报酬模板等。

    数据源校验
        导入并核对第三方数据：
            证券价格（交易所收盘价、中债估值、中证估值）；
            权益公告（分红、除权除息信息）；
            货币基金万份收益、债券利率调整等。
        异常监控：系统自动触发价格偏离阈值报警（如涨跌幅超10%的证券）。

2.日间数据采集与预处理

    交易数据对接
        自动接收投资交易系统的成交数据（股票、债券、回购等），并与TA系统（登记结算系统）同步份额变动。
        处理场外交易：通过直连接口读取银行间债券交易、大宗交易数据，生成清算指令。

    特殊业务处理
        停牌证券：采用指数收益法或可比公司模型估值，需托管行复核并公告方法。
        债券利息：按票面利率每日计提应计利息，付息日重置归零。
        费率调整：监控公告生效的费率变更（如管理费下调），更新系统参数避免净值错误。

3.日终清算与估值核算

    资产计价与负债确认
        资产计价：
            股票：取交易所收盘价；
            债券：取中债/中证估值或模型定价（如含权债）；
            衍生品：按Black-Scholes等模型计算。
        负债计提：
            自动计算当日应付管理费、托管费（年费率/365摊提）；
            记录应付赎回款、交易结算款。

    自动化清算与凭证生成
        批量执行清算指令，系统自动生成会计凭证（如：债券利息收入、股票买卖成本）。
        支持“一键清算”：整合持仓核对、成本结转、损益计算等步骤。
    
    NAV计算与交叉验证
        执行公式：NAV = (总资产市值 - 总负债) / 总份额。
        通过三重校验确保准确性：
            与托管行电子对账（持仓、现金余额）；
            跨系统比对（TA系统份额 vs 估值系统持仓）；
            内部双人复核大宗交易、停牌股估值。

4.风控与异常处理
    
    全流程稽核监控
        系统实时扫描400+监控项（如净值波动超0.5%、费用计提遗漏）。
        示例：若费率调整未生效，触发报警并定位到具体产品。
    
    估值误差处理
        误差超阈值（如0.5%）时：
            暂停披露，复核数据源及计算逻辑；
            人工干预调整净值，管理人承担赔偿；
            向监管报备并公告说明。

5.报表生成与信息披露

    核心报表输出 
        自动生成：
            估值表（资产明细、NAV）；
            资产负债表、损益表；
            监管报表（如保监会格式）。
        支持多维度统计：如分组合净值、跨账套合并报表。
    
    数据披露与归档
        导出净值至证监会指定平台及第三方销售渠道（天天基金、支付宝）。
        数据库备份：完整保存当日所有操作日志及版本快照。

6.系统优化与维护

    性能提升措施 
        自动化工具： 
            脚本自动抓取交易所行情，较原系统效率提升50%；
            电子对账提速5倍，批量账务处理提速1倍。
        热部署升级：稽控指标可自定义配置，T0生效无需停服3。
